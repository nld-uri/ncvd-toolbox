The decomposition

One state record, two identities, both exact

With displacement, velocity and acceleration at nn stations, the toolbox writes the state record and its rate as

𝐗1=[𝐪, 𝐪˙]=𝐔𝚽𝖧,𝐗2=[𝐪˙, 𝐪¨]=𝐔𝚲𝚽𝖧+𝐑\mathbf{X}_1=[\mathbf{q},\ \dot{\mathbf{q}}]=\mathbf{U}\boldsymbol{\Phi}^{\mathsf{H}},\qquad \mathbf{X}_2=[\dot{\mathbf{q}},\ \ddot{\mathbf{q}}]=\mathbf{U}\boldsymbol{\Lambda}\boldsymbol{\Phi}^{\mathsf{H}}+\mathbf{R}

where 𝐔\mathbf{U} is the temporal basis, 𝚽\boldsymbol{\Phi} the characteristic shapes, 𝚲=diag(λi)\boldsymbol{\Lambda}=\operatorname{diag}(\lambda_i) the characteristic values (poles) and 𝐑\mathbf{R} whatever no linear model of the record explains: noise, unmeasured forcing, nonlinearity. The first identity is always exact; the second is exact for a clean linear record, and each pole is paired with its shape by construction.

The readout

Rotating by the eigenvectors of the coupling matrix makes the decomposition exact

The decomposition builds on the characteristic value decomposition (CVD/GCVD) of Li, Stein and Chelidze (2025). It forms the same balanced quotient of second moments and its eigenvectors 𝐕\mathbf{V}, then diagonalises the coupling matrix and rotates:

𝚺2=𝐕𝖧𝐁𝐕−𝖧=𝐓𝚲𝐓−1,𝐔=𝚵𝐓,𝚽=𝐕𝐓−𝖧\boldsymbol{\Sigma}_2=\mathbf{V}^{\mathsf{H}}\mathbf{B}\,\mathbf{V}^{-\mathsf{H}}=\mathbf{T}\boldsymbol{\Lambda}\mathbf{T}^{-1},\qquad \mathbf{U}=\boldsymbol{\Xi}\,\mathbf{T},\qquad \boldsymbol{\Phi}=\mathbf{V}\,\mathbf{T}^{-\mathsf{H}}

The values are then the eigenvalues of the least-squares state-rate operator 𝐁=𝐗1†𝐗2\mathbf{B}=\mathbf{X}_1^{\dagger}\mathbf{X}_2. Reading them from the diagonal of 𝚺2\boldsymbol{\Sigma}_2 instead is exact only when 𝐕\mathbf{V} already diagonalises it. The balanced quotient applies the Joukowski map λ↦12(λ+λ−1)\lambda\mapsto\tfrac12(\lambda+\lambda^{-1}), which folds the pole plane at the unit circle; averaged ensemble quotients and nonlinear windows also break diagonality. There the diagonal readout errs at second order in the poles and first order in the shapes.

Practical data

Derivatives, sensor noise, forcing and many records

Rates computed from displacement by any FIR stencil return the stencil symbol of the pole, not the pole itself:

λ~=d(eλΔt),d(θ)=fs∑jcjθj,λ=fslogθ\tilde\lambda=d\!\left(e^{\lambda\Delta t}\right),\qquad d(\theta)=f_s\sum_j c_j\,\theta^{j},\qquad \lambda=f_s\log\theta

Inverting the symbol recovers the pole to machine precision for forward, central, five-point and Savitzky–Golay stencils, inside each stencil's band.

Nonlinear systems

Sliding windows trace frequency-energy dependence from one free decay

Each short window of a decay is decomposed; its values are the best linear description of the local dynamics. Following each resonance through the windows gives the data-driven counterpart of a nonlinear normal mode backbone curve, and the window residual shows how strongly each window engages the nonlinearity.

  1. Excite every resonance you track; check the singular values of each window.
  2. Span at least one period of the slowest mode per window; a dozen is comfortable.
  3. Watch weak modes: a superharmonic of a strong mode can take a weak mode's pole slot.
  4. Validate every pole against the measured response frequency (band_frequency).
  5. Trust frequencies and shapes; damping from single nonlinear windows scatters.

Get started

Using the code

Python (NumPy and SciPy):

git clone https://github.com/nld-uri/ncvd-toolbox.git
cd ncvd-toolbox/python && pip install -e .

import ncvd as nc
rec = nc.ncvd(d, v, a)                  # X1 = U Phi^H, X2 = U Lam Phi^H + R
mp  = nc.modal_parameters(rec.lam)      # wn, wd, zeta
tr  = nc.track(d, v, a, fs=fs, length=800, step=400, M=M)   # backbones

MATLAB (base MATLAB, R2022a or later):

addpath('ncvd-toolbox/matlab')
rec = ncvd.decompose(d, v, a);
mp  = ncvd.modalParameters(rec.lam);
tr  = ncvd.track(d, v, a, Fs=fs, Length=800, Step=400, M=M);

Both packages share the same API and are tested against each other. The user manual covers the theory, the options and seven worked examples; the repository README lists the contents.
